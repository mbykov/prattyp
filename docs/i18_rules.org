* Принципы построения i18n/<lang>.json

Каждый языковой пакет описывает отображение слов на типы токенов.
Код не содержит языко-специфичных строк — всё в JSON.

* Слои обработки

1. Острова (find_islands) — выделяют математические фрагменты в тексте
2. Токены (tokenize_island) — превращают слова в типизированные токены
3. PREP-разрешение (resolve_prepositions) — определяет роль предлогов по контексту
4. Парсер (parser.py) — строит AST из токенов
5. Генератор (generator_typst.py) — AST → строка Typst

* Структура языкового пакета

** numbers
Числительные: "один" → 1, "двадцать" → 20, "сто" → 100.
decimal_marker: слова-разделители целой и дробной части ("целых", "точка").
decimal_10/100/1000: знаменатели ("десятых", "сотых", "тысячных").

** variables
Имена переменных: "икс" → x, "игрек" → y, "пи" → pi.
Специальные константы: "бесконечность" → inf.

** functions
Однословные имена функций: "синус" → sin, "косинус" → cos.
Используются в неявном режиме: sin x + y all → sin(x + y).
Явный режим: sin ( ... ) → sin(...).

** func_phrases
Многословные имена функций: "натуральный логарифм" → ln.
Обрабатываются ДО отдельных слов в токенизаторе.
Слова из фраз автоматически добавляются в math_start/math_continue.
Используются для: ln, integral, def_integral, contour_integral, lim.

** operators :: binary
Операторы и их синонимы: "плюс" → +, "умножить на" → *.
Фразы проверяются ДО connectors — порядок важен.

** keywords
Одиночные ключевые слова — запускают конструкции:
- frac: "дробь"
- divide: "разделить"
- integral: "интеграл"
- sqrt: "корень"
- paren_auto: "скобка" (нечётная = открывающая, чётная = закрывающая)
- square/cube: "квадрат", "куб"
- numerator/denominator: "числитель", "знаменатель"
- degree: "степени"
- diff: "дэ", "де" — разделитель для интегралов
- at: "при" — STOP-маркер для lim
- quote: "кавычки" — строковая переменная

** all
Слова для группировки: "всё", "все".
На верхнем уровне: оборачивают всё слева в скобки.
Внутри функций: закрывают неявный режим (LIFO).

** connectors
Слова, которые можно безопасно проглатывать в любом контексте:
- "аргумента", "функция", "функции"
- "извлечь", "результат", "деления", "величина"
- "деленная", "слеш", "частное", "отношение"
- "точке", "стремящемся", "функции"
- "пределах", "пределы"
ВАЖНО: не добавлять сюда слова, которые уже есть в operators, functions, keywords,
или PREPOSITIONS. Иначе они будут проглатываться до того, как их обработает
нужная ветка токенизатора.

** prep_resolution
Правила разрешения PREP-токенов по контексту.
Формат: { "контекст": { "preps": [...], "action": "..." } }

Контекст — это значение последнего значимого токена перед PREP
(KEYWORD, FUNC, или "expr" для верхнего уровня).

Действия (action):
- "of"     → OF      (разделитель для sqrt, root)
- "sep"    → SEP     (разделитель для frac, divide)
- "power"  → KEYWORD:pow  (возведение в степень)
- "stop"   → STOP    (разделитель аргументов для lim, sum)
- "ignore" → IGNORE  (проглатывается, для "от" после func)

Пример:
- sqrt + из → OF
- frac + на → SEP
- lim   + при/в/на/к → STOP
- func  + от → IGNORE
- expr  + на/к → SEP

* PREPOSITIONS (в tokenizer.py, но должно быть в JSON)
Предлоги, которые становятся PREP и разрешаются по контексту:
"в", "во", "на", "из", "от", "под", "к", "по", "над", "до", "при".

* Острова и островки

** Остров (island)
Фрагмент текста, похожий на формулу.
Начинается словом из math_start.
Продолжается пока слова в math_continue.
Разрывается при встрече слова вне math_continue.

** Островок (внутри парсера)
Конструкция со своим контекстом: frac{}{}, sqrt{}, ^, integral...d.
Внутри островка ALL работает по обычным правилам в пределах этого контекста.
Границы островка определяются ключевыми словами и STOP-маркерами.

** Конец выражения
- ALL на верхнем уровне: группирует всё слева
- ALL внутри функции: закрывает неявный режим
- STOP: разделяет аргументы (для lim, sum)
- SEP ("на", "дэ"): разделяет операнды в frac, divide, integral
- OF ("из"): разделяет степень и подкоренное в sqrt/root

** Середина выражения (в дроби)
Числитель: от frac до SEP ("на") или ALL.
Знаменатель: от SEP до ALL или END.
Если нужна группировка внутри знаменателя: ALL или скобки.

* Правила добавления новых слов

1. Если слово — математический оператор → operators
2. Если слово — имя функции (одно слово) → functions
3. Если слово — имя функции (несколько слов) → func_phrases
4. Если слово запускает конструкцию → keywords
5. Если слово — предлог → PREPOSITIONS (пока в коде) + prep_resolution
6. Если слово можно проглотить без вреда → connectors
7. Если слово — числительное → numbers
8. Если слово — имя переменной → variables

* Порядок обработки в токенизаторе (важен!)

1. number_map, decimal_markers
2. all_set
3. func_phrases (_try_match_func)
4. keyword_phrases (_try_match_keyword_phrase)
5. keyword_map
6. func_map
7. var_map
8. op_map (_try_match_op)
9. PREPOSITIONS → PREP
10. connector_words → проглатывается
11. fallback (символы, цифры, латиница)
12. resolve_prepositions (POST-обработка)

Слова из func_phrases и keyword_phrases не должны дублироваться в connectors,
иначе они проглатываются до того, как их найдёт _try_match_*.
