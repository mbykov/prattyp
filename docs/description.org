* Prattyp — архитектура и алгоритм

Голосовой ввод математических формул → Typst.

* Общий pipeline

[голос] → [текст] → [нормализатор: острова] → [токенизатор островов]
       → [парсер: Pratt + группировка] → [AST] → [генератор Typst]

* Слой 1: Нормализатор — выделение математических островов

**Вход:** строка текста (результат распознавания речи).
**Выход:** список «островов» — фрагментов текста, похожих на формулы.

Остров начинается словом из =math_start= (числа, переменные, функции, ключевые слова, all, минус, символы операторов).
Остров продолжается словами из =math_continue= (все выше + операторы + all + слова-связки + символы).
Остров закрывается при встрече слова вне =math_continue=.

**Пример:**
"посчитай икс плюс два и три умножить на четыре"
→ остров 1: ["икс", "плюс", "два"]
→ остров 2: ["три", "умножить", "на", "четыре"]

* Слой 2: Токенизатор острова

**Вход:** список слов одного острова.
**Выход:** список токенов.

Типы токенов: =NUM=, =VAR=, =FUNC=, =OP=, =ALL=, =KEYWORD=, =SEP=, =PAREN_OPEN=, =PAREN_CLOSE=, =END=.

Словари берутся из =i18n/<lang>.json=. Код не содержит кириллицы.

**Скобки:** слово "скобка" — нечётное вхождение = открывающая, чётное = закрывающая (счётчик в пределах острова).
Синонимы: "открывающая скобка", "закрывающая скобка".

**Fallback:** цифры распознаются как =NUM=, латиница — как =VAR=, символы =+=, =-=, =*=, =/=, ====, =<=, =>=, =(=, =)= — как соответствующие токены. Это позволяет использовать внешний препроцессор.

**PREP-токенизатор:** Все предлоги (в, на, из, от, при, к, когда...) поступают как =PREP=.
После токенизации =resolve_prepositions= определяет роль каждого PREP по контексту
(последний значимый токен перед PREP). Правила разрешения — в =prep_resolution= в JSON.

* Слой 3: Парсер — Pratt parser с группировкой ALL

** 3.1. Приоритеты операторов (binding power)

| Оператор          | left_bp | right_bp |
|-------------------|---------|----------|
| =                 | 1       | 0        |
| ==, !=            | 2       | 0        |
| <, <=, >, >=      | 3       | 0        |
| +, -              | 4       | 5        |
| *, /              | 5       | 6        |
| унарный -         | —       | 7        |
| функция (неявный) | —       | 3        |
| ALL               | 0       | —        |

=right_bp = 0= для сравнений означает: правая часть — независимый островок, ALL работает на верхнем уровне.

** 3.2. ALL — закрывающая скобка без парной открывающей

ALL имеет bp = 0 (самый низкий приоритет).

*** На верхнем уровне (min_bp = 0): ALL группирует всё выражение слева в =ParenNode= и продолжает.

1 + 2 all + 3 → (1 + 2) + 3
1 + 2 all = x + y all → (1 + 2) = (x + y)

*** Внутри бинарного оператора (min_bp > 0): ALL прерывает цикл (break без advance), возвращая left наверх. Вызывающий уровень увидит ALL и сгруппирует свой left.

a + b * c all + d:
  1. parse_expression(0): left = a
  2. peek = +, bp=4 ≥ 0 → right = parse_expression(5)
  3. parse_expression(5): left = b; peek = *, bp=5 ≥ 5 → right = parse_expression(6) → c
  4. left = b * c; peek = ALL, min_bp=5 > 0 → break, возврат b*c
  5. parse_expression(0): left = a + (b*c); peek = ALL, min_bp=0 → ParenNode(a+b*c)
  6. peek = + → + d
  Результат: (a + b * c) + d

** 3.3. Функции: явный и неявный режим

После токена функции (=sin=, =cos=, ...):

*** Явный режим: если следующий токен — =PAREN_OPEN=.
Аргумент ограничен парной закрывающей скобкой. ALL внутри скобок работает как обычно, но не может закрыть функцию — только =)= её закроет.

sin ( a + b ) + c  →  sin(a + b) + c
sin ( a + b all ) + c  →  sin((a + b)) + c

*** Неявный режим: если следующий токен — ЛЮБОЙ другой (число, переменная, функция, оператор).
Аргумент продолжается до ALL на этом же уровне контекста (min_bp = 3). Внутри могут быть вложенные функции или скобки — они определяют свой собственный контекст.

sin a + b all  →  sin(a + b)
sin log a + b all all  →  sin(log(a + b))
sin a + (b + c) + d all  →  sin(a + (b + c) + d)

*** Жадность функции (FUNC_BP = 3): позволяет захватывать =+=, =-=, =*=, =/= внутрь аргумента.
ALL имеет bp = 0 < 3 → прерывает неявный режим.

** 3.4. Вложенные функции (LIFO)

ALL закрывает ближайший неявный контекст (Last In, First Out).
Лишний ALL на верхнем уровне — безвреден, группирует всё слева.

sin cos a + b all all  →  sin(cos(a + b))
a + sin cos a + b all all all / 3  →  (a + sin(cos(a + b))) / 3

** 3.5. ALL внутри явных скобок

ALL внутри =(...)= работает как на верхнем уровне: группирует внутри скобок, но скобку не закрывает.

sin ( a + b all + c )  →  sin((a + b) + c)

** 3.6. Явные скобки =( ... )=

Открываются =PAREN_OPEN=, закрываются =PAREN_CLOSE=.
Создают изолированный контекст: внутри — новый вызов =parse_expression(0)=.
ALL не может закрыть скобку. Скобка не может закрыть неявный контекст функции.

** 3.7. Frac и Divide

*** Frac: =frac <числитель> на <знаменатель>=
Числитель: от =frac= до =на=. ALL внутри числителя работает по общим правилам.
Знаменатель: от =на= до ALL или END.

*** Divide: =разделить <левый> на <правый>= или =<левый> разделить на <правый>=
Превращается в бинарный оператор =/=. Сложные операнды оборачиваются в =ParenNode=.

** 3.8. Пределы (lim_func) — поиск по частям

Конструкция предела функции не зависит от порядка слов.
Парсер ищет составные части по ролям STOP-токенов (роли заданы в =prep_resolution=):

- =func_arg= ("от") — аргумент функции: f(x)
- =condition= ("при", "когда") — переменная, которая стремится
- =target= ("к") — цель, куда стремится
- =context= ("в") — точка или бесконечность: "в точке x", "в бесконечности"
- =target_mod= ("на", "с") — модификатор цели

Парсер последовательно собирает: функцию (первый VAR + func_arg/скобки),
затем переменную (condition) и цель (target) в любом порядке.
= в середине предела обрабатывается на верхнем уровне.

Примеры:
"предел f от x при x к a" → lim_(x -> a) f(x)
"предел f(x) когда x к a" → lim_(x -> a) f(x)
"предел f при x к a от x" → lim_(x -> a) f(x)

* Слой 4: AST

Узлы:
- =NumNode=, =VarNode= — терминалы
- =BinOpNode=, =UnaryOpNode= — операторы
- =FuncNode= — функция с аргументом
- =FracNode= — дробь (числитель, знаменатель)
- =ParenNode= — скобки (явные или результат группировки)
- =AllNode= — маркер =all= (уходит при группировке)
- =LimNode= — предел (function, variable, target)

* Слой 5: Генератор Typst

Рекурсивный обход AST → строка Typst.

- =NumNode= → число
- =VarNode= → имя переменной
- =BinOpNode= → =left op right=
- =UnaryOpNode= → =-operand=
- =FuncNode= → =name(arg)=. =ParenNode= вокруг аргумента убирается (скобки функции достаточно).
- =FracNode= → =frac(num, den)=
- =ParenNode= → =(inner)=. Двойные скобки схлопываются: =((x))= → =(x)=.
- =LimNode= → =lim_(variable -> target) function=
